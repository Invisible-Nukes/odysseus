### Real bug found + fixed
The download retry-loop comment promised retries fall back to the plain downloader, but **hf_transfer was never disabled on retry**. If hf_transfer hiccuped, every retry re-enabled it and re-crashed.
- Fix (`routes/cookbook_routes.py`): on retry attempts (`_attempt > 1`), when hf_transfer enabled, re-export `HF_HUB_ENABLE_HF_TRANSFER=0` + lower `HF_HUB_DOWNLOAD_MAX_WORKERS`. Applied to both the local-Windows and remote-bash HF retry loops. Ollama / explicitly-disabled paths untouched.
- Added `tests/test_cookbook_hf_reachable.py` coverage (2 new tests) asserting the fallback line is emitted and the wrapper is valid bash.
