# Odysseus Cookbook Path Remediation Session — 2026-06-25

## Overview

Deep audit of Cookbook download, cache, GGUF discovery, and serve path handling on Windows, followed by a seven-workstream multi-agent remediation, dead-code cleanup, environment rebuild, and partial manual VM smoke test. This session builds on the 2026-06-23 Windows compatibility work by addressing the backend/frontend path contract break that left downloads landing in `DATA_DIR/huggingface` while JS and probes still assumed Unix `~/.cache` paths.

## Session Goals

1. Scan Cookbook pathing, downloading, GGUF setup, and serve flows for mis-download and wrong-directory risks
2. Document findings in a consolidated audit with multi-agent workstreams
3. Create and execute a remediation plan (Analyst → Scaffolder → Executor → Verifier per workstream)
4. Remove dead code orphaned by the path-contract fix
5. Wipe/rebuild the Windows dev environment under `C:/odysseus`
6. Run manual VM smoke test to validate the path contract end-to-end

### Phase 4: Remediation Implementation ✅

**Commit `bd7106e`** — `fix(cookbook): align Windows download, scan, and serve path contract`

20 files changed (+1958 / −163 lines). Major changes:

#### Backend (`routes/`, `src/`)
- **`resolve_python_for_probe()`** — uses `sys.executable` / `shutil.which("python")` instead of hardcoded `python3` for HF cache probes (CB-DL-002)
- **`resolve_cookbook_log_path()`** — unified log path resolution for local Windows, local POSIX, remote Windows (A2-01)
- **`win_session_stop_tree_ps()`** — Windows PID-tree kill parity (CB-DL-001)
- **`_build_dl_pyarg()`** — passes `include` filter to Python `snapshot_download` fallback (CB-DL-004)
- **`_safe_env_prefix_ps()`** — PowerShell-safe venv/conda activation for remote Windows (A2-02)
- **`_strip_path_trailing_seps()`** — normalizes Windows trailing backslashes (CB-DL-012)
- **`model_cached`** — injects `HUGGINGFACE_HUB_CACHE` constant into scan; wires `add_hf_cache` when `is_wsl()` (A3-01, A4-1)
- **HF cache incomplete probe** — checks snapshots on Windows, not just `blobs/` (A2-04)
- **Remote Windows stderr** — merged into status poller output (CB-DL-003)
- **`disable_hf_transfer`** — honored in PowerShell download path (CB-DL-009)
- **`_state_for_client()`** — exposes `defaultHubPath`, `localPlatform` to frontend
- **Agent tools** — `download_model` forwards `local_dir`; task registration includes `local_dir`, `platform`; Windows PID kill; log paths via resolver (CB-DL-005, CB-DL-006, CB-DL-001)

#### Frontend (`static/js/`)
- **`_defaultHubPath()`** — canonical hub path from server `env.defaultHubPath` (A5-002)
- **MiniMax M3 serve preset** — uses `_defaultHubPath()` instead of hardcoded `/home/pewds/.cache/...` (A5-001)
- **Serve GGUF expr** — falls back to `_defaultHubPath()` not `$HOME/.cache` (A5-004, A3-02)
- **`_normalizeState()`** — maps legacy `~/.cache/huggingface/hub` to server default (A3-03)
- **Download preview** — shows HF_HOME/hub layout, not flat `local_dir=` (CB-DL-007)
- **Zombie duplicate check / hwfit kill** — use injected `_tmuxCmd` / Windows stop tree (CB-DL-010, CB-DL-015)
- **Diagnosis cache cmd** — Windows branch uses `%USERPROFILE%` (A5-005 partial)

#### Tests added
- `tests/test_cookbook_path_contract_regression.py` — no pewds paths; `_defaultHubPath` usage
- `tests/test_cookbook_log_path_resolver.py` — log path resolver
- `tests/test_cookbook_windows_stop_tree_js.py` — JS log path guards
- `tests/test_hf_download.py` — HF download script env seeding
