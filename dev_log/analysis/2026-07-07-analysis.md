## 2. Root-Cause: PyPI 10054 (External Blocker)

**Symptom:** `pip install -r requirements.txt` deterministically fails with `ConnectionResetError(10054)` to `https://pypi.org/simple/fastapi/` from Python's TLS stack. PowerShell `Invoke-WebRequest` succeeds; other HTTPS sites from Python succeed. Failure is PyPI-edge-specific.

**Plausible causes (research):**
| Cause | Likelihood |
|-------|-----------|
| Antivirus/web-protection injection into `python.exe` (Kaspersky-style) | High |
| Windows proxy/firewall mismatch (Python doesn't inherit WinHTTP settings) | High |
| TLS/ALPN/HTTP-2 profile mismatch with PyPI Fastly edge | Medium |
| TLS/CA bundle path issue | Low (Fix C sanitization didn't change behavior) |

**Safe mitigation:** regional HTTPS mirror (`PIP_INDEX_URL`). Both `tuna` and `aliyun` verified installing `fastapi` cleanly in isolation.

**Unsafe (avoid):** blanket `--trusted-host=*`, random proxies, global OpenSSL/pip replacement, AV tampering.

**Resolution applied:** `launch-windows.ps1` now defaults `ODYSSEUS_PIP_MIRROR` to `https://pypi.tuna.tsinghua.edu.cn/simple` when unset. User can override via env var.

## 3. Mirror Fallback Root-Cause (Why It Didn't Trigger)

The automatic fallback only fired inside the post-retry `$LASTEXITCODE -ne 0` branch with a log tail matching `ConnectionResetError|10054`. In the live failure run, the install function returned observing `$LASTEXITCODE = 0` (stale exit code from an earlier successful step, or pip reporting success despite incomplete cache), so the `if ($LASTEXITCODE -ne 0)` block — which contains the fallback — was skipped entirely. Result: "Dependencies installed successfully" printed, then `setup.py` crashed on `ModuleNotFoundError: httpx`.

**Fix:** made `ODYSSEUS_PIP_MIRROR` a default (not a fallback that must trigger correctly), added step-scoped exit codes, and added `Test-OdysseusDepsReady` post-install gate so false success can't pass.

## 7. Lessons Learned (Applied to Memory)

1. **Root-cause wrapping:** when a working workaround exists, use it directly — don't build elaborate fallback layers.
2. **Subagent self-report ≠ verification:** always verify runtime state with live runs.
3. **End-to-end early:** syntax validation alone is insufficient; run reset → launch → HTTP probe in one cycle.
4. **Subagent fan-out discipline:** don't spin up 3 parallel subagents for linear problems.
5. **Stop whack-a-mole:** if each live run surfaces one new bug, do a fuller static pass first.
6. **Verification criteria:** for PowerShell, AST parse is necessary but not sufficient — confirm the script completed its actual job.
