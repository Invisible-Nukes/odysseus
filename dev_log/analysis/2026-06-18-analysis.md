# 2026-06-18 — Dependency Download Analysis (Consolidated)

**Topic:** Reliability of Cookbook dependency/model downloads.
**Key finding:** 14 verified real issues + 3-4 likely issues across config, environment detection, device/hardware, network handling, and prerequisite validation. System has strong error recovery but lacks proactive pre-flight validation.

## Critical / High issues
- **CUDA version incompatibility:** vLLM needs CUDA 11.8+; never checked before install. Wastes 2GB+ download that fails at runtime.
- **No pre-flight disk space check:** downloads fail mid-stream → corrupted `.incomplete` files.
- **Build tools not validated:** cmake/git/gcc not checked before llama.cpp build → "command not found".
- **Non-adaptive timeouts:** fixed 10s/8s/120s; fail on slow links and 1GB+ packages.
- **Fixed 30s retry backoff:** no exponential backoff or failure classification.
- **llama-cpp-python CPU-only wheel index:** `https://abetlen.github.io/llama-cpp-python/whl/cpu` hardcoded → GPU users get no acceleration.
- **No AMD ROCm support:** hardware.py only nvidia-smi.
- **Driver error messages truncated** to 140 chars (loses diagnostic context).

## Config / compat gaps
- Undocumented proxy support (`src/tls_overrides.py`) — no tests.
- No GPU compute-capability check (older GPUs can't run vLLM models).
- No system-memory pre-flight check.
- Python version compatibility not validated.

## Test status
- ✅ `test_environments.py` 36/36, `test_pip_command_builder.py` 53/53, `test_cookbook_helpers.py` 65/65 (sampled).
- ❌ No tests for CUDA, disk-space, build-tools, adaptive timeout, AMD ROCm.

## Root-cause patterns
1. **Reactive not proactive** — errors detected after they occur, not prevented.
2. **Hardcoded config** — 30s retry, 120s timeout, 8 workers, CPU wheel index all hardcoded.
3. **Platform bias** — Nvidia-only; no AMD/Apple/Intel Arc.

## Follow-up plan
CUDA detection module, disk-space pre-flight, build-tools checker, adaptive timeouts, network-aware retry, AMD ROCm framework, GPU compute validator.
