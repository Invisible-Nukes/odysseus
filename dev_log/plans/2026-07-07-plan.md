# 2026-07-07 Plan — Windows Launcher/Reset Fixes

Status: draft  
Scope: concrete changes to `launch-windows.ps1` and `reset.ps1` only.  
Focus: eliminate the current install/TLS failure mode, harden error leakage, and make reset behavior truthful.

---

## 1) Short-term fixes

### Fix A: Replace `*>` with explicit tee-style log capture
- **File:** `launch-windows.ps1`
- **Change in `Install-OdysseusDependencies`:** change `& $venvPy @($step.Args) *> $installLog` to:
  `& $venvPy @($step.Args) *>&1 | Tee-Object -FilePath $installLog`
- **Why:** `*>` requires PowerShell 6+, but the script declares `#Requires -Version 5.1`. The tee pattern preserves real-time-readable output and works on 5.1.
- **Also fix same pattern** anywhere else `*>` is used.

### Fix B: Detect `ConnectionResetError(10054)` as cache-corrupt / retryable
- **File:** `launch-windows.ps1`, line 210
- **Change:** extend regex to include `ConnectionResetError|10054`
- **Why:** this is the live failure signature from the analysis; without it the script hard-fails instead of purging cache and retrying.

### Fix C: Clear pip TLS env contamination before install
- **File:** `launch-windows.ps1`
- **Change:** before any pip command, sanitize:
  ```
  $env:SSL_CERT_FILE = $null
  $env:PIP_CERT = $null
  $env:PIP_INDEX_URL = $null
  $env:PIP_EXTRA_INDEX_URL = $null
  ```
  then optionally set `SSL_CERT_FILE`/`PIP_CERT` to `$venvDir\Lib\site-packages\certifi\cacert.pem` if it exists.
- **Why:** Hermes Agent may have injected a bad `certifi` path into these variables. The current logic unconditionally copies Hermes `certifi` and re-injects if present. We need it only if Hermes certifi is healthy, otherwise prefer the venv cert store.

### Fix D: Preflight `data/logs` write access and disk space
- **File:** `launch-windows.ps1`
- **Add before pip starts:**
  1. try `New-Item -ItemType Directory -Path $logsDir -Force | Out-Null`, fail early with a readable message if blocked.
  2. check free space on the script drive, require >500 MB; fail early if insufficient.
- **Why:** current failures below the path layer are silently attributed to PyPI.

### Fix E: Set `$ErrorActionPreference` around native pip calls in `Ensure-ChromaDbPackage`
- **File:** `launch-windows.ps1`, function `Ensure-ChromaDbPackage`
- **Change:**
  - save/restore `$ErrorActionPreference` around `& $venvPy -m chromadb-client ...`, set local to `Continue`
  - read `$LASTEXITCODE` and emit a synthetic terminating error if nonzero.
- **Why:** line 21 sets `$ErrorActionPreference = "Stop"`; native stderr from chromadb-client can abort the launcher instead of degrading gracefully.

### Fix F: Make reset truthful about locked/partial deletions
- **File:** `reset.ps1`
- **Change:**
  1. Remove `$ErrorActionPreference = 'SilentlyContinue'`
  2. Use explicit `try { Remove-Item ... } catch { ... }` blocks with a failure summary counter.
  3. Final message says either `Reset complete.` with count, or `Reset incomplete; N paths still locked or failed.`
- **Why:** current silent suppression hides failures from locked `data/logs/*.log` held by resident uvicorn. Claimed "Reset complete" can be wrong.

### Fix G: Make uvicorn exit code deterministic
- **File:** `launch-windows.ps1`, around lines 608-622
- **Change:** after the drain loop and stream closes, before any `throw`/`Read-Host`, explicitly `exit $proc.ExitCode` (or `0` if already clean). Catch/`finally` should `exit 1` on forced shutdown path.
- **Why:** observed `4294967295` is never produced by scripted exits; removing the ambiguity removes a misleading diagnostic.

## 3) Fallback behavior if network/TLS persists after fixes

After applying A–E, if pip still fails:

1. **Disable Hermes certifi injection entirely for the install step.**  
   Prefer venv `certifi` or system store; never inherit Hermes cert file.

2. **Use plain Python CLI diagnostics before pip.**  
   Run `$venvPy -c "import urllib.request; print(urllib.request.urlopen('https://pypi.org/simple/').status)"`.  
   If this fails with 10054 outright, the fault is outside pip and likely Schannel/OpenSSL policy or proxy offload.

3. **Temporarily add an HTTP index mirror as a last fallback** only for bootstrap, not long-term:  
   `$env:PIP_INDEX_URL = 'http://localhost:8080/simple'` pointing at a local simple-index if offline mirroring is available; otherwise accept degraded offline mode.

4. **Explicit offline/compat mode.**  
   If still broken, write `odin_compat/requirements-pinned.txt` bundle check or force `Test-OdysseusDepsReady` to skip pip when packages are importable; otherwise surface exact diagnosis:
   - write `pip install` stdout, stderr, env vars to `data/logs/pip_install_<ts>.log`
   - ask user to toggle VPN/proxy/offload and retry.

## 4) Done criteria

1. `launch-windows.ps1` loads under Windows PowerShell `5.1` with no parser error on `*>`.
2. `pip install -r requirements.txt` succeeds on a clean `venv` on the first clean attempt without Hermes certifi path contamination.
3. If `ConnectionResetError(10054)` occurs, the script purges pip cache and retries instead of failing immediately.
4. `reset.ps1` reports exact deletion results; no `SilentlyContinue` blanket suppression.
5. Launcher exit code is `0` for normal uvicorn shutdown, nonzero only for real failures; no `4294967295`.
6. Chromadb install failure degrades vector RAG without crashing the launcher.
7. A guaranteed validation path: rerunning `launch-windows.ps1` after `reset.ps1` reaches uvicorn without rerunning pip when deps are already importable.
