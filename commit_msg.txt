## Issue Fixed

Previously, pip was generating --user --break-system-packages flags even inside virtualenvs, causing 'User site-packages are not visible in this virtualenv' errors. Models could not be downloaded and run locally.

## Solution

- Detect venv/conda/bare Python environments at runtime
- Conditionally add --user flag only when NOT in a venv
- Add --break-system-packages only in bare environments
- Centralized all pip flag logic to prevent inconsistencies
